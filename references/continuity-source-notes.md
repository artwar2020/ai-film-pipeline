## 采纳方式

角色与场景描述复用、资产状态分离、空间地图、行为化表演、单变量迭代和粗剪反馈是本规范采用的方法。它们是项目制作经验，效果仍需在当前素材、模型与任务上验证。

CINEDANCE 的提示词结构和镜头诊断作为已读案例纳入，但其针对 Seedance 2.0、Higgsfield 的具体视角数字、标签语法和 UI 设置只在目标工具确实支持时使用。所谓“静默 QA”是写作前的内部检查，不应把检查清单直接塞进最终生成提示词。其“只输出最终提示词”也只适用于用户明确要求该格式的场景；规划、比较和复盘仍应解释假设与未验证之处。

下列内容不作为固定要求：

| 来源中的经验或说法 | 本规范的处理 |
|---|---|
| 角色参考正面身体不带头 | 仅在模型误用参考表中小脸时考虑调整参考布局，先测试。 |
| 十次资产测试全部通过 | 是团队经验，不是普遍保证；覆盖实际使用条件并尊重预算。 |
| 迭代十到十五次再拆镜头 | 不是最低尝试次数；发现结构问题即可提前拆分。 |
| 每个片段开头先用约一秒全景 | 可测试的定位手段，不强迫所有镜头使用；也不证明独立生成间有记忆。 |
| 每一两秒有一个微表情 | 可用于检查僵硬感，不机械计数，表演节奏服从情境。 |
| 全身从首帧运动、同时又要求首秒静止 | 原文存在张力；按镜头目的选一个一致方案，避免照搬冲突文本。 |
| 长提示词三千至四千词 | 不设字数目标；按工具上限保留必要信息，减少每个动作段的负担。 |
| 单一光源、写实风格、禁止配乐 | 是团队风格与后期选择；通用要求是光源逻辑自洽、风格一致。 |
| 8K、IMAX 等质量词 | 只代表风格或质量意图，不等于实际输出规格。 |
| 更改措辞或隐藏年龄以避开审核 | 不纳入规范；不以规避平台安全机制为目标，不隐瞒必要信息。 |
